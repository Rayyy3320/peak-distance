# M1：网页学习闭环

历史阶段方案，仅用于追溯。当前产品约定见 [PRD](../PRD.md)，当前任务见 [ROADMAP](../ROADMAP.md)。本文件中的阶段限制和交付指令不再作为当前任务要求。

## 0. M0 收尾

修改 `entrypoints/youtube-inject.content.ts`，各保留一个可重复的时序回归检查：

| 已复现顺序 | 当前问题 | 修复后结果 |
| --- | --- | --- |
| 当前视频 A → 地址变为 B → 捕获 B 的 timedtext → 收到 B 的 config | 捕获时内部仍是 A；config 重置清掉刚捕获的 B URL，未开始拉取 | 捕获前同步视频身份，或重置时保留已属于 B 的来源；不靠 nudge 重抓才能继续 |
| 同视频 en 请求在途 → 捕获 fr 轨道 → en 响应返回 | en 正文带上读取自当前 sourceUrl 的 fr trackId，并被接收 | 请求固定来源和轨道身份；旧轨道结果被丢弃，新轨道正文与元数据一致 |

保留正常取字幕和跨视频旧响应丢弃检查。真实 Chrome 再验证一次站内切换，记录视频 ID、状态和首条字幕；通过后更新 ROADMAP 的 M0 状态。当前辅助 CDP 脚本尚未完整跑通，不作为必经路径；不扩建代理探测或浏览器启动方案。

## 1. 网页选词

- 新增通用网页 content script；M1 启用于普通 HTTPS 网页及 X，跳过 YouTube（沿用 M0 脚本）。不处理输入框、contenteditable、iframe 或 PDF 阅读器。
- 用户选中一个词或短语后，选区附近出现查词入口。点击入口固定表达、所在正文片段、来源 URL 和标题；不自动请求全文或抓取 X thread。
- 弹窗展示表达、原文上下文、中文释义与语境说明、保存、已掌握及当前状态。关闭支持 Esc；复制、链接和原有选区继续可用。
- 新选区替换旧弹窗；旧请求返回时不能覆盖新选区。保存始终使用当前弹窗固定的快照。
- 无 key 时提供设置入口；请求中、解释失败时均可保存原文。保存成功与失败分别反馈，不用乐观提示代替数据库结果。

## 2. DeepSeek 释义

用户指定：DeepSeek V4.1 Flash。默认直连官方 API，不添加服务选择器或通用 provider 框架。

| 配置 | 值 |
| --- | --- |
| Endpoint | `POST https://api.deepseek.com/chat/completions` |
| API model | `deepseek-flash` |
| 调用位置 | background，原生 fetch，非流式 |
| 输入 | 选中表达、所在原句及必要邻近文本 |
| 输出 | 简短中文释义 + 当前语境说明；用纯文本展示，不渲染模型 HTML |
| 设置 | API key 输入、保存、更换；不内置凭据 |

采用低延迟的官方支持模式，接入时核对请求参数。一次查词对应一次请求；失败提供手动重试，区分未配置、鉴权失败、限流及网络错误。上下文文本作为待解释材料传入。

模型名与 endpoint 已于 2026-10-01 核对：[模型发布](https://api-docs.deepseek.com/zh-cn/news/news260910/)、[首次调用](https://api-docs.deepseek.com/zh-cn/)。`deepseek-flash` 是服务别名；显示名称为 DeepSeek V4.1 Flash。

## 3. 保存与生词本

- 按 [PRD](../PRD.md) 实现规范化去重、saved / learning / known 和上下文追加。重复保存已有词条保持其当前状态；用户显式修改状态时才改变。
- 以 background 中的 IndexedDB 为学习数据来源；词条规范化键唯一，词条与上下文在一次事务中保存。
- 网页上下文按词条、URL、原文片段去重；网页不伪造视频时间。原文保留大小写，释义允许为空。
- 解释返回前已保存的上下文，在本次解释成功后补上释义，不能追加重复上下文或写入别的选区；失败保留已保存原文。
- 侧栏由扩展按钮打开：词条列表、按表达搜索、上下文详情、状态修改、删除、打开来源。搜索无结果与尚无收藏分别显示。
- 多标签页查询同一表达时读到同一状态；保存或修改后，已打开的侧栏刷新对应数据。删除词条连同上下文删除。

## 4. 落点与权限

- 保留当前 WXT + TypeScript + DOM/CSS。现有 `entrypoints/background.ts` 接入消息、存储与请求；新增网页入口、侧栏和设置页，以及实际使用的词汇 / 存储 / DeepSeek 模块。
- `shared/protocol.ts` 仍是 YouTube 页面桥协议；扩展内部词汇消息不借道 window.postMessage。只定义实际使用的消息和类型。
- 申请本阶段需要的 storage、sidePanel 和 DeepSeek 主机权限；网页读取范围与 content script 匹配范围一致。
- key 存在 chrome.storage.local，并限制为受信任扩展上下文可访问。content script 只传查词材料和词汇操作，不传任意请求地址或凭据；background 校验消息来源与载荷。
- M1 不实现双语渲染、网页词汇高亮、词形归并或复习。仅在第 0 节触及现有字幕逻辑。

## 5. 验收与交付

1. `npm run typecheck`、`npm run build` 通过；第 0 节时序回归通过。
2. 普通文章与 X 各实测“选词 → DeepSeek 真实释义 → 保存 → 侧栏回看”。先完成无 key 的本地链路；真实服务验收由用户在设置中填写 key，mock 不计为服务通过。
3. 同一表达不同大小写不重复建词条；同一上下文重复保存不增加记录；新语境追加。修改状态、跨标签页读取、删除后查询均与持久化结果一致。
4. 重启浏览器后读回词条和上下文；无 key、请求失败和响应晚于新选区时，仍能保存正确原文。先保存后返回释义不产生重复记录。
5. 对归一化去重、事务保存 / 删除、过期解释归属保留最小可重复检查；浏览器覆盖选区、弹窗、侧栏和设置的真实入口。

交付实际命令、改动摘要、验证结果及未通过项；更新 README 和 ROADMAP。缺少真实服务或浏览器验收时保留 M1 待验收状态。
