## 10. 缺陷清单

### 缺陷 1（P1）：新消息发送后立即「已中断」，必须手动重试才开始生成

- 文件：问答链路（侧栏 → `blc-chat` 端口 → background SSE；怀疑发送时序/端口握手）
- 复现：任一会话（文章/视频/X）输入问题发送 → 消息立即显示「已中断」+「重试」；点重试后正常生成
- 频率：4/4（100%）
- 期望：发送后直接进入流式生成；「已中断」应只在真实中断（SW 重启/端口断开）时出现
- 备注：render-check 的「继续问 chatEnsure 载荷」与 e2e「单条问题」均过，说明载荷与单条链路逻辑正确；差异在真机侧栏端口的建立时序

### 缺陷 2（P2）：「问 AI」未带入句级引用

- 文件：字幕列表 hover「问 AI」入口（`blc-chat-source` 直达消息载荷）
- 复现：字幕列表任意行 hover → 点「问 AI」→ 问答视图切到视频会话，但无「引用：m:ss · 句子」卡片（与文章侧「继续问」带入引用卡行为不一致）
- 期望：按 spec 带入所点句子的引用，问「这一段在讲什么」时引用聚焦该句

### 缺陷 3（P2）：引用面板跨会话残留

- 文件：`#chat-cite-panel` 生命周期管理
- 复现：文章会话点 [p177] 打开引用面板 → 切到视频/X 会话（或清空会话）→ 面板仍显示上一会话的 [p177]/[p247] 内容；仅手动点 × 关闭
- 期望：切换会话或清空会话时引用面板随会话关闭
- 备注：p247 面板在视频会话清空后仍残留，已作为缺陷 3 的补充证据

### 观察项

1. 信息流广告帖建立的 status 会话：广告帖无真实 /status/ 详情页（X 返回「页面不存在」），该会话完成后无法再进入 → 无法用「清空」清理（本次测试遗留 1 条 Venice 会话消息，无副作用）
2. 「继续问」不自动开侧栏：spec §8 第 1 行期望「侧栏打开且带引用卡片」，实际只提示手动打开。若为有意设计（避免强行抢占侧栏），建议更新 spec
3. 生词本 tab 中出现「当前页面对话」入口卡（Project management - Wikipedia），含材料/引用/清空按钮——非工单描述的形态，建议核对设计
