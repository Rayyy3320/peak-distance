# YouTube 原文字幕语言排查与修复

日期：2026-10-06。范围：用户截图的阿拉伯语原文字幕与无法改变语言。

## 实机证据

用户已打开视频 `GjN3xLDuc8o`：

- 播放器实际选轨为 `ar / asr`，扩展诊断记录与显示文本也为阿拉伯语；中文行是该阿拉伯语字幕的译文。
- 播放器音轨为英语原声。轨道表有 21 条自动字幕，阿拉伯语为索引 0，英语为索引 3；默认音轨索引 2 的 `defaultCaptionTrackIndex` 为 3，即英语。
- 扩展启动日志为 `boot → cc-on → tracklist → cues ar`，没有 nudge。因此可确认本次扩展沿用播放器阿拉伯语轨道，但不能证明本次初始阿拉伯语选择由扩展的兜底分支引发；初始选择发生前的播放器状态没有被记录。
- 原生设置有完整语言列表。通过「Settings → Subtitles/CC → English (auto-generated)」切换后，播放器与扩展均变成 `en / asr`，可见英语原文及中文译文。没有复现原生菜单无法切换。
- 扩展「双语」菜单没有原文语言入口；设置中的理解语言控制译文和释义，不能改变原文字幕。这是扩展内无法改变原文语言的直接原因。

## 子 agent 审查确认的根因

- `new URL(url, '')` 对绝对地址也会抛错，旧轨道身份函数因此直接返回带 pot 的原始 URL；签名、过期时间和参数顺序也混入身份。同轨道续期会误触发换轨／丢弃在途结果。
- 待取偏好、明确选轨与捕获来源分别决定结果，靠不同位置的过滤补偿。原生选轨又仅在网络捕获时读取：缓存命中没有网络时不会同步；异步 setOption 的旧读数可能覆盖新意图。
- 取消只 abort 在途 controller，获取仍有效，迟到捕获会用同一 nonce 重启；原文失败后的同目标重试也不能依赖“轨道发生变化”才发请求。
- 语言＋类型不足以区分具名／变体轨道，播放器描述往返还需保留实际身份字段。原文与译文分别处理 URL／pot，会保留旧凭据。

## 最终实现

- `shared/subtitleTracker.ts` 统一轨道描述、稳定内容身份、播放器确认值、明确目标和捕获归属；签名／令牌与内容身份分离，旧 Resource Timing 按请求开始时刻过滤。换轨或取消保留当前视频最近携带 pot 的凭据，换视频清除。
- MAIN 只保留一条获取路径，原生选轨通过既有播放器轮询观察，缓存命中也能获取对应轨道；明确目标等待确认时，旧确认值不代表新意图。原文、已有译文轨和平台翻译复用目标签名＋最近 pot 的 URL helper。
- 初始化同完整语言优先人工轨，初始化之后尊重手动及原生选择；无当前轨时使用默认音轨声明的字幕，缺依据时不猜第一项。获取开始、取消、导航、唤醒与重试收口，取消直到新 config／选轨才恢复。
- 删除 `prefer` 协议、`pendingPrefer`、隔离世界自动选轨与语言过滤、重复 CC 重启、无用 force 分支；隔离世界只展示已取得字幕与待完成操作。失败保留可用原文，菜单按播放器高度滚动。
- 保存去重、词卡匹配、整句收藏显示／取消及学习库合并复用稳定身份。旧记录按规范化身份匹配，删除仍使用原记录 ID，不批量改写用户资料。

## 验证与边界

- 新增的默认选轨、语言入口检查在旧构建上失败，修复后通过。
- `npm run verify-local`、`node tools/render-check.mjs` 与 `npx tsx tools/m11-vault-format-check.ts` 通过。覆盖完整轨道身份、签名／pot 续期、旧记录去重、延迟确认、缓存原生换轨、具名轨道、同目标重试、首次人工优先及后续手动自动轨、取消后迟到捕获，以及既有译文、AP、显隐与导航行为。
- 小播放器菜单渲染截图位于 `.upstream/subtitle-language-menu.png`；受控页面使用模拟字幕与网络结果，不代替真实服务验收。
- 实机完成的是原生菜单切换与扩展跟随。新增原文语言控件尚需用户重新加载扩展、刷新视频后验收，不能用当前已恢复英语的旧页面声称新构建已生效。
