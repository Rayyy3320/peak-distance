# M10：问答会话与查词交互修正

状态：0.4.1 已实施，本地验收通过，用户 Chrome 实机出口见 [M10 报告](m10-verification-report.md)。2026-10-03 用户确认的行为和指定组件优先于 M5–M8 中冲突的旧约定；交付状态由 [ROADMAP](../ROADMAP.md) 维护。

## 1. 目标与依据

消除空会话堆积及删除后自动补建；在历史行内使用指定 Delete Button 完成删除确认；选区入口只保留一层表面；词卡外点击即可关闭并继续网页操作。

| 已核对的问题 | 当前代码依据 |
| --- | --- |
| 读活动会话、新建会话都调用 `ensureChat({})`，立即写入 `conversations` | `lib/chatService.ts` 的 `chatActive/chatNew`；`lib/db.ts` 的 `ensureChat` |
| 删除后前端立即刷新活动会话，定时轮询也走同一条自动创建路径 | `entrypoints/sidepanel/chatView.ts` 的删除回调与 `pollChatSource` |
| 删除与清空使用浏览器原生确认框 | `chatView.ts` 的 `confirm()` |
| 查词入口外壳与按钮各自带背景、边框、圆角 | `entrypoints/web.content.ts` 的 `ensurePill` 与 `shared/brand.ts` |
| 外部点击关闭依赖 `pinned.anchor`，网页选区打开词卡没有提供该锚点 | `shared/lookupPopup.ts` 与 `web.content.ts` 的 `openPopup` |

这是源码核对结论；用户截图是实际痛点证据，不等于本轮已运行产品验收。

## 2. 会话与临时编辑

### 保存边界

- 打开 AI 问答、点击新对话、输入文字、附加材料或带入引用，都不创建持久化会话。界面可显示“新对话”和输入框，无会话 ID 是正常状态。
- 首次发送通过问题长度、配置等现有前置校验后，将会话、首条用户消息、所用材料／引用及回答占位一起提交；不先落一个空壳。本地提交成功后才清空输入并启动生成。
- 前置校验或本地提交失败：保留临时内容，不新增历史。已提交后的网络失败、停止或中断：保留已发送问题及相应状态，沿用重试入口。
- 后续输入和尚未发送的材料／引用修改同样属于临时编辑；历史消息绑定的材料快照不变。发送成功后，新材料成为该会话已提交的上下文。
- 活动会话读取不自动创建记录；旧 ID 已删除时返回空态。空态、请求失败分开处理，读取失败不能覆盖当前输入。

### 用户确认的“离开”边界

| 操作 | 未发送内容 |
| --- | --- |
| 新建对话、成功切换到另一会话 | 丢弃当前临时输入、材料与引用修改；切换失败仍保留 |
| 明确关闭面板、关闭承载页面／窗口、重新加载扩展 | 丢弃；重新打开不恢复未发送内容 |
| 切换生词本、复习、设置等模块 | 保留临时内容 |
| 切换浏览器标签页 | 保留临时内容 |
| 固定／浮动模式切换，以及全屏容器移交 | 保留临时内容；切换失败保留原容器内容 |
| 仅打开／关闭历史列表 | 保留临时内容 |

临时内容与已提交内容必须分开：离开已有会话只丢弃本轮未发送修改，返回时仍可使用最后已提交的材料。新会话丢弃后回到空态。不增加“是否保存草稿”弹窗或草稿历史页。

实现可复用窗口级工作区临时状态及现有模式移交机制；不写入会话库或永久存储。若使用 `storage.session` 移交，显式关闭后清除，重新打开不能当作可恢复草稿。不要仅凭 `visibilitychange` 或连接断开判定用户关闭：标签切换和模式切换也会触发这些事件。

### 删除与清空

- 删除非当前会话：当前内容不变。删除当前会话：保留历史列表及滚动位置，当前内容回到未保存的新对话空态；没有剩余会话时显示历史空态。
- 删除成功才移除列表行和清除活动 ID。失败保留原对象并在该行提示，可再次操作。删除生成中的会话沿用现有取消路径，迟到结果不能写回。
- 新建／切换／删除时失效旧的读取及临时编辑回写；复用操作身份检查，不引入通用任务调度或全局锁。
- 清空仍清除当前消息和材料，不影响生词本；清空后的纯空白不继续作为新历史条目保存。未保存空态的清空不发数据库请求。
- 旧版本记录不做自动批量删除；已有零问记录仍可逐条删除，不能仅按问题数误删带材料或草稿的旧数据。旧版本持久化草稿的批量迁移另行处理，本轮不增加清理工具。

## 3. Delete Button：按指定源码复刻

唯一参考为用户指定的 [Moumen Soliman / NativeDelete](https://21st.dev/@moumensoliman/components/delete-button)。用户最终确认：**英文、结构、尺寸和动效按原组件保留；材质采用现有纸感，颜色允许在红色系内适配整体调性**。这是对原色要求的明确修订，不改成红字链接、独立弹窗或“删除某会话？”文字面板。

源码快照见 [native-delete.tsx.txt](../references/native-delete.tsx.txt)。页面公开使用示例及 [公开预览](https://cdn.21st.dev/moumensoliman/delete-button/default/bundle.1768800782521.html) 已核对；完整组件由用户提供，`./button` 与主题文件未提供，静态外观补充依据为公开预览的实际计算样式。来源信息见 [REFERENCES](../REFERENCES.md)。

### 交互和视觉合同

| 项目 | 基准 |
| --- | --- |
| 默认版本 | `md`，显示图标；主按钮高 40px、圆角 8px，14px / 20px、500 字重，水平内边距 16px |
| 默认态 | 白字红底，Trash2 + `Delete`；原预览背景为 `oklch(0.577 0.245 27.325)`，产品允许调整为与纸色协调的低饱和暖红 |
| 确认态 | 同一个按钮变为 Check + `Confirm`，右侧展开 ×；按钮间距 8px |
| 取消按钮 | 40×40px、1px 细边框、8px 圆角，可访问名称 `Cancel delete`；原预览为白底／浅灰线／近黑图标，产品改用现有纸色表面、分隔线与墨灰 |
| 图标 | 原 Lucide Trash2 / Check / X 路径，16×16px，描边 2；主按钮图标右间距 8px |
| 布局变化 | `spring`，`bounce: 0`，`duration: 0.35`；保留展开和收起的布局过渡 |
| 图标切换 | 先出后入，透明度 0↔1、缩放 0.8↔1，各阶段 0.15s；初次显示不播放入场动画 |
| 文本切换 | 先出后入，从 y=4、透明度 0 到正常，退出到 y=-4、透明度 0，各阶段 0.15s |
| 取消按钮进出 | 透明度 0↔1、缩放 0.8↔1、x=-8↔0，退出不占据最终布局空间 |
| 悬停／按下 | 主按钮 1.02 / 0.98；取消按钮 1.05 / 0.95；主按钮禁用时无缩放交互 |
| 禁用 | 主按钮不可点击，透明度 0.5、禁用光标；保留原按钮焦点及悬停样式，按预览核对 |

纸感复用现有低对比纸纹，文字和图标保持不透明；不新生成纹理，不加入高光、玻璃或厚重拟物边框。红色及其悬停态在实现时与当前米白背景一起校准，满足现有文字对比要求，不在 spec 中凭空指定最终色值。材质与配色是授权适配项，其余以原组件为基准。

源码参数是实现基准，不把 `spring` 随意替换成普通 `ease` 后声称 1:1。尺寸按 CSS 布局核对，不能用悬停缩放后的截图尺寸作为默认尺寸。该组件 350ms 动效是项目默认动效时长的明确局部例外；减少动态效果设置仍应生效。

### 接入现有列表

- 每行以会话 ID 绑定按钮；第一次点击只展开确认，第二次才删除，× 收起。源组件没有外部点击／Esc 收起处理，本轮不额外改变它的确认机制。
- 源码的 `onConfirm` 只表示进入确认态，不发删除请求。`onDelete` 接实际异步删除；确认后按原组件收起，等待期间禁用该行 Delete，成功移除行，失败恢复可用并显示就近错误。演示中的两秒后恢复按钮不接入产品。
- 历史刷新不销毁未变条目的确认态或反复播放入场动画；不要为此重建整个历史列表。标题允许换行，操作区按最大展开宽度容纳；窄布局优先将操作放到下一行，不缩小组件或压扁动画。
- “清空”共用该局部实现，传入已有功能名称“清空”及 `Confirm`，避免把清空错误命名为 Delete；空态不出现可提交的清空确认。
- 工程仍使用 TypeScript + DOM/CSS。优先按原参数用原生动画实现局部组件，不为一个按钮引入 React、Tailwind 或整套 shadcn。若原生方案不能忠实复现原弹簧，应报告具体差异，再决定是否引入最小动画依赖；不能静默降级。无需照搬当前未使用的大小及配置分支。

## 4. 选区入口与词卡关闭

- 查词／翻译入口只有一个带底色、边框、圆角和阴影的外层操作条，内部按钮取消独立边框及常驻底色。保留既有文字、可见性规则、命中区和键盘焦点；悬停可使用浅蓝底。
- 词卡打开时隐藏相应选区入口；旧选区和延迟的选区事件不能立即把入口重新显示出来。新选区可以正常触发下一次查询，不用清除原文选区来掩盖问题。
- 完整词卡与字幕紧凑词卡都支持外部点击关闭，不依赖定位锚点。点击同时继续执行所点网页操作；不覆盖透明遮罩、不吞掉点击、不在外部关闭后强行恢复旧焦点。
- 卡内选字、切词典、保存、展开义项和拖动不误关。拖动始于卡内、结束于卡外不当作一次外部点击。点击另一个词时直接切换到新词，旧关闭事件不能关掉新词卡。
- 保留显式关闭和 Esc。外部关闭复用已有取消请求／`onClose`，迟到结果不重开卡片，YouTube 暂停／恢复沿用原约定。
- 点击范围覆盖网页正文和扩展自己的工作区；跨自有 iframe 使用现有扩展通信传递关闭意图，不读取 iframe 内文档，不建立通用页面消息代理。该规则关闭的是词卡，不是主工作区。
- 同类选区翻译卡同步采用外部点击关闭。普通页面内任意第三方 iframe、浏览器地址栏等不纳入本轮全局点击监听。

## 5. 修改边界与进一步简化

| 责任 | 预计落点 |
| --- | --- |
| 临时编辑、空态、发送和列表行确认 | `entrypoints/sidepanel/chatView.ts`、`main.ts` 及现有样式 |
| 首次发送提交、活动 ID、删除与取消 | `lib/chatService.ts`、`lib/db.ts`、`shared/messages.ts` |
| 模式移交与真实关闭区分 | `lib/panelService.ts`、`shared/floatingPanel.ts` 及已有工作区快照 |
| 选区入口和弹层关闭 | `entrypoints/web.content.ts`、`shared/lookupPopup.ts`、`shared/translationPopup.ts`；按需接入 YouTube／工作区入口 |
| 原组件移植 | 一个局部 DOM 组件及其样式，记录来源；不扩成全站确认框系统 |

本轮值得顺手消除的重复：旧草稿自动落库与离开时保存路径、删除／清空原生确认框、未变列表全量重绘、词卡打开后旧选区入口重现。只删除被本轮接管的逻辑。

保留现有轮询频率和消息通道；修正读取语义即可解决自动补建，不另做事件总线改造。不增加回收站、撤销队列、批量清理、草稿中心、历史搜索、通用弹层框架或数据库升级，除非实现证据表明当前结构确实无法完成已确认行为。

## 6. 验收与交付

| 验收场景 | 通过条件 |
| --- | --- |
| 空会话 | 首次打开、连续新建、轮询及删除当前会话后的多个轮询周期，均不产生空会话；核对数据库和界面 |
| 首次发送 | 未配置／问题超限／提交失败不落空记录；一次有效发送只产生一个带首问的会话；生成失败仍可恢复该问题 |
| 临时编辑 | 输入＋材料＋引用分别经过模块切换、标签切换、固定／浮动移交后保留；换会话、关闭重开后丢弃，已发送内容不丢 |
| 关闭识别 | 扩展关闭按钮、Chrome 原生侧栏关闭、浮动工作区关闭均正确；仅隐藏标签、移交容器或 worker 恢复不误判成用户关闭 |
| 删除 | 当前／非当前／最后一条／生成中会话；列表位置正确，失败不移除；旧响应不覆盖空态或新选择 |
| 原组件 | 对照默认、确认、取消、悬停、按下和禁用状态；核对英文、尺寸、图标、动效顺序与时长；纸感和红色适配与当前 UI 协调，轮询不重置确认 |
| 查词入口 | 单词及多动作选区无双重边框；开卡后旧入口不重现；新选区正常工作 |
| 词卡关闭 | X／普通网页、YouTube 和自有工作区；外部链接／按钮／输入框只执行一次原操作，卡内操作和拖动正常，播放状态正确 |
| 清空 | 面板内确认；清空后回到未保存空态，生词本不变 |

实施阶段运行 `npm run typecheck`、`npm run build`、`npm run regress`，更新并运行与会话生命周期相关的 `e2e-check` 和工作区移交 `check-m8`。旧的“重启恢复未发送草稿”断言改为本 spec 约定；不要把历史迁移内容完整性的检查一起删除。网络使用隔离测试数据，界面确认在窄／宽工作区集中完成，原生侧栏关闭另做真实 Chrome 检查。

只给会话保存、删除竞争、状态移交等行为增加能发现回归的检查。按钮数值和轻样式不建立逐属性快照测试；与公开预览集中比对即可。检查通过即结束，无关 AI 供应商、字幕网络专项不因本轮反复执行。
