# 学习库集合文档与双向同步

用户反馈：Chrome / Edge 点击同步后词语、句子不一致，Obsidian 中逐词创建文件造成持续增长的散文件。按本次要求替代 M11 的逐词／逐句文件组织。

## 结果与边界

```text
学习库/
  生词本.md
  句子.md
  对话/...
  材料/...
  偏好.md
  .peak-distance/...
```

- 词语、句子各一份 Markdown，记录按稳定 ID 分节；每个会话继续一份 Markdown，材料组织沿用现有实现。
- 记录受管属性写在 YAML 围栏中；“我的笔记”、自定义属性和小节保留。集合有独立格式标识，不能把分隔标记丢失的正文误判成空库。
- 完整词典结果、时间、词形、视频位置保存在共享辅助数据中，另一浏览器读回时不依赖原浏览器私有信息。
- 旧词语／句子散文件合并后重新读取核对，源文件备份在辅助目录。删除源文件前复读校验；外部改动导致冲突时停止归档，保留源和备份。
- 旧句子文件没有持久化的字段无法凭空恢复：稳定 ID 可恢复视频、轨道和起始位置；准确结束位置、标题和完整释义须由保留这些字段的原浏览器写入。本次未清空任何原浏览器的数据。

## 根因与实现

- 旧同步路由忽略读回／权限错误，句子导入缺少列表变化通知；页面提示与实际提交结果不一致。手动同步现在返回实际写入、读回和错误结果，刷新词语／句子集合；页面负责在点击时重新请求目录权限。
- 旧文件序列化没有完整持久化词条字段和视频关联；句子解析结果直接强制转换成本机记录，不能形成可用的视频句子。统一记录映射与共享恢复数据提供完整记录。
- 同一 worker 的保存、读回和集合替换串行执行；待办修订号防止旧提交清除新修改。补队列、导入和远端删除在数据库事务中验证最新记录和待办；本机删除与删除待办同事务提交。
- 不使用时间优先或“已掌握优先”裁决状态／笔记冲突。单边修改或不同字段修改合并，同字段分歧保留本机和文件内容，报告冲突。

## 验证

- `npm run typecheck`、`npm run build`、`npm run regress`。
- `npx tsx tools/m11-vault-format-check.ts`：记录往返、未知内容保留与合并规则。
- `node tools/vault-sync-check.mjs`：真实 Chrome / Edge 独立 IndexedDB、生产同步与格式代码共用一份磁盘目录；只有目录句柄边界采用适配。覆盖词语／完整释义／视频句子交换、重复同步、不同字段合并、旧快照与新待办竞争、删除提交、并发保存保护、句子笔记、损坏文档和迁移备份。
- `node tools/m11-vault-e2e.mjs`：构建后的真实扩展、原生 OPFS 目录句柄和实际消息路由；通过设置页点击同步读回句子，并检查权限拒绝、格式损坏与冲突反馈。
- 独立源码与确定性竞争复查已完成，未发现剩余阻断项。

尚未验证用户实际授权目录的 Chrome / Edge 原生权限恢复、同时替换写及外部编辑器互斥。写前／写后校验和串行 worker 不能证明跨程序原子提交；迁移复读与删除之间仍存在原生 API 无法原子化的最窄间隙。此前的用户浏览器连接错误也未作为实机通过证据。

原生权限约束依据：[Chrome File System Access 文档](https://developer.chrome.com/docs/capabilities/web-apis/file-system-access)。可写流模式依据：[FileSystemFileHandle.createWritable](https://developer.mozilla.org/en-US/docs/Web/API/FileSystemFileHandle/createWritable)。
