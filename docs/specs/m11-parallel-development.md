# M11 执行组织与续工 Prompt

本文件替代原三独立聊天方案。产品范围、UI/UX 和验收仍以 [M11 spec](m11-multilingual-local-vault.md) 为准。

## 1. 唯一执行入口

- I 对整个 M11 负责：实现、必要委派、集成、验证及进度更新。
- 用户只与 I 沟通；不需要创建 L/V 聊天、转发消息、提交号或协调合并。
- 保留已建立的独立仓库、现有分支、提交和未提交实现，沿当前工作继续。
- 取消固定三线程、B0/C0 发布门槛和原文件归属限制。共享接口由 I 随实际实现确定，不等待另一个聊天接手。

## 2. 按需使用子代理

I 以自身实现为主，只委派边界明确、能独立完成的工作；通常同时零到两个子代理即可。

| 工作 | 执行方式 |
| --- | --- |
| 语言身份、共享类型、数据库迁移、后台接线、主 UI | I 连续实现 |
| 免费渠道／分词验证，文件系统独立探针 | 可并行委派，返回结论、证据和失败用例 |
| 输入输出已明确的新模块或局部检查 | 可委派实现，限定具体文件 |
| 依赖当前未定接口、频繁跨模块改动的任务 | I 自行完成 |
| 最终集成与 M11 验收 | I 负责；可委派独立复核 |

- 子代理由 I 创建、传递上下文、接收结果和续派，用户不充当中间人；没有可用子代理工具时 I 串行继续。
- 委派说明只需目标、输入／接口、可写文件、检查方法和返回内容。
- 子代理共享目录时，同一文件同时只由一方修改；接管前明确交还写入权。测试输出、浏览器配置和临时学习库分别隔离。
- 默认复用当前工作目录；只有独立写入任务确需隔离时才使用 worktree，由 I 管理基线与集成。子代理不在共享目录切分支或合并代码。
- I 不等待无关子任务才继续主线；依赖项未返回时先推进可独立部分。已验证结论不由其它代理重复验证。
- 结果直接回给 I，最终汇入 M11 验收报告；不要求每个子任务再维护一份交接文档。

## 3. 接续当前工作

- I 继续已有语言／存储基础改动，按 M11 的 A–E 依赖推进；文件系统未验证的能力先做探针。
- 已有分支和 worktree 保留待 I 判断用途，不因组织方式变化重建、重置或清理工作。
- 普通实现选择、修复和相关测试由 I 完成；只有产品取舍、真实技术阻塞或必须由用户完成的浏览器授权需要用户输入。

## 4. 发给 I 的续工 Prompt

~~~text
继续当前 M11 工作，保留已有仓库、分支、提交和未提交改动。

执行组织改为“你独立负责完整交付，按需使用内部子代理”。读取更新后的 docs/specs/m11-parallel-development.md；它替代此前固定 I/L/V 聊天、B0/C0 等待和文件归属要求。功能与验收继续以 M11 spec 为准，UI/UX 沿用其中列出的现有规范。

我明确允许你使用子代理处理独立验证、复核或边界清楚的局部实现。由你负责委派、传递上下文、接收结果、解决冲突及集成；不要让我新开 L/V 聊天或传递消息。通常零到两个子代理即可，不为凑并行拆任务；没有子代理能力时你串行完成。

共享类型、数据库迁移、后台接线和主 UI 由你推进。委派写入时限定文件，避免与自己的修改重叠；worktree 仅在必要时使用并由你管理。继续完成 M11 的实现、相关验证和进度记录，仅在真实阻塞或产品取舍时询问我。
~~~
